# CLAUDE.md — PitchLab

Guidance for Claude Code when working in this repo. Read this before making changes.

## What this is

**PitchLab · by VENOMYZER** is a football tools web app with a console-game style UI (think the main menu of an EA Sports FC game, but with all-original graphics and sounds). **Streamer Tools is the main function**: it gets the hero tile on the main menu and new work should favour it. Three sections, in priority order:

- **Streamer Tools**: match scoreboard overlay for OBS plus its control panel
- **Tactic Boards**: Formation Lab and Tactics Sandbox (also used on stream via clean view)
- **Learn Football**: interactive lessons (offside so far)

Target users: football streamers (watch-along streams) first, and football fans learning the game. The app must be good enough that other streamers adopt it, so polish and reliability matter more than feature count.

## Hard rules (product decisions, do not change without the owner asking)

1. **No backend, no accounts, no live data.** Everything runs in the browser and saves to `localStorage`. Don't add APIs, servers, databases or football data feeds.
2. **No club crests, league logos, kit designs, player photos, or EA/FIFA/FC branding or assets.** Teams are coloured dots and text. All sounds are generated by `scripts/make-sfx.mjs`. Don't add downloaded sound or image assets without a clear licence.
3. **Never invent football facts.** Rules come from IFAB Laws of the Game. Formation shapes are labelled "typical, simplified". Don't add real team setups, stats or results unless the owner supplies them.
4. **Stream safety comes first** (see below). A streamer must never get stuck or embarrassed live.
5. **Product name lives in `src/config.ts`.** Never hardcode "PitchLab" elsewhere in new code.

## Stack

- React 19 + TypeScript + Vite 8
- Tailwind CSS v4 (CSS-first config via `@theme` in `src/index.css`, no tailwind.config file)
- Framer Motion for animation
- Howler for sound
- react-router-dom v7 (`BrowserRouter` normally, `MemoryRouter` when `VITE_PREVIEW=1`)
- Fonts are self-hosted via `@fontsource`: Big Shoulders Display (display), Archivo (body), JetBrains Mono (keys). The OBS scoreboard uses `font-broadcast` (Saira Condensed) so site restyles never change the stream. Pitch SVG labels still name Saira/Barlow.
- `public/profile/` holds the owner's profile card media (see its README.md). Only the owner's own or licensed files go there.
- `public/bg/menu-1920.jpg` is a 1920px web copy of the owner-supplied, free-to-use stadium image. Never use it on `/overlay`.
- Deployed on Vercel at https://pitchlab10.vercel.app (pushes to `main` go live). `vercel.json` rewrites all routes to `index.html` and caches hashed `/assets/*` for a year. OBS uses the deployed https URL (copy links are built from `window.location.origin`); the panel and overlay must be on the same origin for sync.

## Pitch coordinate system

- SVG units are metres. Pitch is `0..105` × `0..68`. Default viewBox `-3 -7 111 83` leaves room for labels above and below.
- **Blue (home) always attacks to the right.** x=0 is blue's goal line. y=0 is the left touchline from blue's point of view.
- Opponents are mirrored with `{ x: 105 - x, y: 68 - y }`.
- Draggable things carry `data-token` (`b:3`, `r:7`, `ball`, or a lesson player id). Pointer handlers find them with `closest('[data-token]')` and convert with `toPitch(svg, e)`.

Formation slots are `[label, defPos, buildPos, attPos]`, where each pos is `[x, y, unit]`. Players with the same unit code form a line, and `shapeOf()` counts lines left-to-right to produce strings like `2-3-5`. If you edit positions, check that the shape string still matches the description text for that phase.

## Scoreboard sync (important)

There is no server. The panel and overlay sync through:
1. `BroadcastChannel('pitchlab-scoreboard')` for instant updates
2. the `storage` event as a backup
3. a 1-second `localStorage` poll as a last resort

Conflicts resolve by `updatedAt` (newer wins). **This only works when the panel and overlay run in the same browser profile**, i.e. both inside OBS (overlay as a Browser Source, panel as a Custom Browser Dock), or both in Chrome. Don't promise phone control. That would need a relay server, which rule 1 rules out.

State shape is versioned (`v: 1`). If you change `State` in `features/scoreboard/state.ts`, keep `readStored()` merging defaults so old saved data still loads. Bump `v` and migrate if a field changes meaning.

All score/clock changes are pure functions on the `A` object (`A.goal`, `A.toggle`, `A.period`, …). Add new actions there, not inline in components.

The clock stores `baseMs` + `startedAt`, so it never drifts and survives reloads. At a period's end it holds (`45:00`) and shows stoppage time separately (`+1:23`), the way TV does.

## Stream-safety rules

These exist because a mistake on a live stream is public. Keep them when editing:

- **Every scoreboard change is undoable** (`Ctrl+Z` / Undo on the panel and the dock). New actions must go through `update()` from `useScoreControl` so they land in history.
- Starting the clock in Pre-match moves to the 1st half (`A.toggle`), otherwise the overlay would keep the clock hidden.
- **Destructive actions need a two-step confirm** inside the page (see `ResetMatch` and Settings). Never use `alert`/`confirm`/`prompt`.
- **Mouse clicks blur buttons** (global handler in `main.tsx`), and Space hotkeys ignore a keyboard-focused button. This stops Space from re-firing the last clicked action. Keep both.
- **The overlay renders nothing while loading** (`Loading` returns null for `/overlay`). Never show spinners, errors or debug text on the overlay.
- Overlay pop-up sounds are **off by default** and only play for events newer than 3 seconds, so reloading OBS never replays a goal sound.
- Hotkeys must ignore typing in inputs and skip when Ctrl/Meta/Alt is held.

## Design system

- Single dark theme on purpose (game UI). Tokens in `src/index.css` `@theme`:
  - `line` hairline outlines, `scrim` see-through panels, `focus` the inverted focus fill
  - `night-*` deep green backgrounds (kept darker and greyer than `turf-*` so the pitch stands out)
  - `mist-*` text
  - `flood-*` amber accent (the one bold colour)
  - `ice-400` secondary
  - `home` / `away` team colours
  - `turf-*` pitch
  - `ok` / `bad` states
- Display text: `font-display font-extrabold uppercase -skew-x-6`. This is the main game-UI look. Use it for titles and verdicts, not body copy.
- Utilities: `cut-corner`, `cut-corner-sm` (angled tile corners), `tabular`, `gutter` (safe-area side padding).
- Focus = inverted (light fill, dark text) via the `focus-invert` class; selected/on = amber. Keep them distinct. Focus moves instantly (no hover lifts or sweeps).
- Menu screens (Shell `menu` + title screen) use a football cursor via the `ball-cursor` class (`src/assets/cursor/`: 32/64 px copies of `ball.png`, `boot-32/64` (copies of `boot.png` with a black border, hotspot on the toe at 1 16) for clickables; rules in `index.css`); tool screens keep normal cursors.
- Corners are near-square (radius tokens 2–4px); `cut-corner` marks menu previews.
- Use `Btn`, `Toggle`, `Segmented`, `Label`, `Panel`, `Kbd` from `components/ui.tsx` instead of new one-off buttons. One-off buttons must add `focus-invert`.
- Every interactive control plays a sound via `sfx.play()`. `Btn` does this by default. Pass `sound={null}` when the handler plays its own.
- Show keyboard shortcuts with `Kbd` / the `hint` prop on `Btn`.
- Respect reduced motion: use `useReducedMotion()` and pass `1` ms durations to `tween` when it's true.
- Menus: use `MenuList` inside `<Shell menu>` (W/S or arrow keys, Q/E tabs; hints show W/S). The status bar is menu-only so tool screens stay clean for screen sharing.

## Copy style

Plain, short, specific. Write for someone who doesn't watch football. Avoid hype words ("powerful", "seamless", "ultimate"), "not X but Y" constructions, and em dashes in UI text. Buttons say exactly what happens ("Add frame", "Hide pop-up"). Errors say what went wrong and how to fix it.

## Known issues / TODO

- `oxlint` reports warnings (refs read during render, setState in effects, `Date.now` in render). They're intentional patterns for animation and clocks, but clean them up when touching those files.
- Libraries are split into a `vendor` chunk (~430 kB: Framer Motion + Router + React) in `vite.config.ts`; app code is ~76 kB. Consider `LazyMotion` if it grows.
- `public/profile/` media is ~15 MB (avatar.gif alone 7.6 MB). Convert large GIFs to mp4/webm before release.
- Not yet tested in real OBS. Before release, test all three setups in `/stream/guide` on OBS 31+.

## Before finishing any change

1. `npm run build` passes.
2. Check the screen at 1920×1080 and at phone width (~400px).
3. For streamer tools: open `/stream/scoreboard` and `/overlay/scoreboard` in two tabs and confirm they sync, then reload the overlay and confirm nothing is lost or replayed.
4. Keyboard-only pass: you can reach and use everything without a mouse, and Esc goes back.
